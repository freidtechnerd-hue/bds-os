# Native x86-64 preview

`make x64` (Windows: `./build.ps1 x64`) produces a genuine ELF64 kernel that
enters long mode, enables paging and runs 64-bit C and native 64-bit RUN apps.
It shares desktop, editor, graphics, input, settings, BDSFS and app-service
sources with the i386 edition. Its interrupt descriptors/handlers and loader
use the x86-64 ABI. It makes no BIOS calls after entering long mode.
Desktop and native RUN icons use 32×32 source frames with transparency;
compact title bars and file rows display a fitted 16-pixel version.

## Boot in a VM

Build with the normal GCC/binutils/NASM/GRUB/xorriso toolchain, then use:

```sh
make x64
cp build/x64/seed.img build/x64/my-data.img
qemu-system-x86_64 -m 256 -cpu qemu64 -vga std \
  -cdrom build/x64/bds-os-x64.iso \
  -drive file=build/x64/my-data.img,format=raw,if=ide,index=0
```

Use a copy of the seed: rebuilding replaces `build/x64/seed.img`. Personal
images and the i386 data image are never modified by the x64 build target.
The ISO is bootable on its own with a read-only live filesystem. Attaching the
raw BDSFS image as the primary IDE master enables persistent files through a
native ATA PIO driver. This preview still needs its ISO to boot; it has no x64
hard-disk installer. The mature installer remains part of the i386 edition.

VirtualBox configuration to try: Other 64-bit, BIOS, at least 256 MiB RAM,
VBoxSVGA, 64 MiB video memory and IDE storage. Convert a **copy** of the raw
seed with `VBoxManage convertfromraw my-data.img my-data.vdi --format VDI`.
The x64 edition is verified in QEMU; its VirtualBox/physical-PC paths are not
verified. Firmware must expose a supported 32-bit RGB framebuffer.

## Native apps

Included: HELLO, CALC, EDITOR, SYSINFO, PUZZLE (2048) and GAME (Snake, Pong, Falling Blocks,
Mines and Star Arcade). Example terminal commands:

```text
RUN /HELLO.RUN
RUN /CALC.RUN 21 * 2
EDIT /NOTES.TXT
RUN /SYSINFO.RUN
GAME snake
```

The x64 loader accepts RUN architecture 3 and rejects architecture 2 (i386).
Apps link at 0x00800000 and use System V AMD64 arguments with 64-bit pointers.
The source-level API resembles i386, but its binary function table layout is
different. Build an app for each architecture; renaming an i386 binary will
not convert it. `api->exit` and ordinary return are supported.

## Current boundaries

This is an early x64 edition, not feature parity with i386. It maps the low
4 GiB and uses a fixed 64 MiB heap; it does not yet use RAM above 4 GiB, multiple
CPUs, process isolation, user-mode programs, EFI-only boot, dynamic linking or
Windows/Linux binaries. A persistent 32 MiB wallpaper cache at 176 MiB
retains the 3840×2160 bitmap; the required 256 MiB profile covers this region. All apps share privilege and fixed address regions.

Storage supports a raw BDSFS primary IDE disk, or the read-only ISO module.
AHCI/NVMe/USB storage, partition discovery, FAT/ISO filesystem browsing and
installation are not ported. Networking, audio, DVD playback, ClassiCube,
DOOM and the NES emulator remain available in the **i386 edition**, not this
preview. Unavailable driver calls return errors rather than pretending to work.
Display uses the boot framebuffer; live VBE mode switching is not available.

`make test-x64` verifies long-mode boot, native programs, read-only rejection,
ATA writes/copy/move, architecture rejection, cold-boot persistence and a
graphical native game on disposable images.
