# BDX-OS desktop update and x64 preview — October 23, 2026

BDX-OS (Binary Development eXperience) is the new name for BDS-OS. Existing
disk formats, RUN headers and developer artifact filenames remain compatible.
The project was directed by freidtechnerd-hue with GPT-6.1 Sol and GPT-6 Astra;
these changes follow the [original video](https://www.youtube.com/watch?v=oUb6CiOTym4&t=10s).

## Changes

- Supplied BDX logos, adapted XP icons embedded in native RUN files, a new
  cloud wallpaper and geometric close/minimize/maximize controls. The boot
  logo appears with the existing three-second animated progress bar.
- Native 32×32 x64 icons, corrected white-background transparency, classic
  dark-blue title bars and a black boot-screen surround.
- Native FreeType TrueType loading, a persistent font picker and antialiased
  text. DejaVu is included; Arial, Times New Roman and Comic Sans were tested
  using local fonts and are not redistributed. Text remains fixed-column ASCII.
- Supplied TADA startup, click interaction, CHORD error and DING notification
  samples mixed with application audio on AC'97 and basic Intel HDA.
- Shared clipboard, editor selection/copy/paste, live system metrics, a UTC
  taskbar clock and reduced idle desktop repainting.
- Faster ClassiCube software rendering, F9 quality selection and an F8 frame
  cap toggle. New native 2048 includes save/resume and one-step undo.
- Browser inline PNGs, bounded back/forward history and address clipboard
  support, alongside the previous TLS 1.2, CSS and limited JavaScript features.
- A real long-mode x64 preview with six native apps, writable raw IDE data,
  TrueType and a 3840×2160 wallpaper bitmap. The generated wallpaper source
  was 1672×941 and resampled; it is not native 4K source detail.
- Updated 8086 text desktop, three color themes and PC-speaker settings.

## Choose an edition

| Download | Use |
| --- | --- |
| Desktop Public ISO | Main i386 BIOS installer with games, browser and media player |
| x64 Preview ISO + Data ZIP | Experimental 64-bit live system; attach a copy of the data image as primary IDE master |
| 8086 IMG | Separate 1.44 MB real-mode floppy edition |

The main installer needs BIOS/CSM and 256 MiB RAM. Installed i386 systems need
128 MiB; use 512 MiB for VM gaming. ClassiCube/media require SSE2; HTTPS needs
RDRAND and a valid UTC clock. The installer erases a selected dedicated disk.
After installation that disk boots without the ISO or USB installer.

The x64 preview needs 256 MiB RAM and still requires its ISO at boot. It has
no installer, networking, audio, optical playback, USB/AHCI drivers or i386
app compatibility. Its six native apps are HELLO, CALC, EDITOR, SYSINFO, GAME
and PUZZLE. See [x64 setup](X64.md) and the [VM/real-PC tutorial](GETTING-STARTED.md).

## Compatibility limits

**DOSBox-X and DOS/Windows EXE execution are unfinished and absent from this
release.** No Windows 3.1/95 installation or Windows game compatibility is
claimed. See [the remaining port requirements](COMPATIBILITY.md).

Apps still run cooperatively with kernel privilege. Native-app minimize pauses
the app in a restore view; it does not add background multitasking. There is
no GPU acceleration. ClassiCube remains offline and silent. The browser does
not reproduce modern PC layouts or full JavaScript/Unicode behavior. Physical
hardware is unverified; firmware determines available display modes.

Public downloads exclude personal ROMs, saves, worlds, Microsoft fonts, VM
disks and downloaded media fixtures. Supplied artwork/audio provenance and
the wallpaper generation prompt are in [the asset notes](../assets/branding/README.md).

### Final ClassiCube measurement

VirtualBox 6.1.50, one vCPU, 512 MiB, VBoxSVGA with 64 MiB video memory,
800×600 desktop, generated world, view distance 32 and uncapped rendering:

- **400×300 balanced:** 68.6–68.6 FPS by host wall time; largest reported
  individual frame 17 ms.
- **640×480 detail:** 55.2–56.1 FPS; largest reported frame 23 ms.

Each run records eight 120-frame samples; the first has no preceding host
timestamp and is excluded from the host-rate range. These are separate
generated-world runs, not identical-scene comparisons. The earlier development
measurement is superseded by these released-binary results. A 60 FPS cap is
available, but a locked 60 FPS result is not guaranteed across worlds or PCs.
